# 旧安全路由最小清理

## 已移除

- `features/settings/dns` 模块及其 Gradle include、应用依赖、导航注册。
- `Screen.DnsResolver` 的序列化注册、页面对象与 `SCREEN_ROUTE_DNS`。
- 网络设置中的旧代理区：`customResolve` 开关、DNS 解析器入口与专用导入；域名切换、超时、Pixiv、豆瓣、更新设置不变。
- 启动时借未读通知接口做连通性探测的逻辑；启动事件直接导航 `Screen.Main`，移除无用构造依赖及 `lastBgmHostCheckTime` 持久化访问和键。通知业务接口本身不变；不主动擦除用户已有数据。
- 确认仅由旧 DNS 页面消费后，移除 `ChoreRepository.fetchDns`、实现、`CloudflareDnsResponse`、`ApiClient.dnsHttpClient`、两个旧 Cloudflare DNS 端点常量。
- Android `System.createHttpClient` 的旧条件分片、静态 hosts DNS 和 TLS 引擎接线；无条件保留 `BgmEchTransport.configure(this)`。确认无其他源码消费者后，仅删除 `AntiSniSocketFactory.kt` 与 `AntiSniTlsEngine.kt`。

旧实现需要回溯时从 Git 历史查阅，不应重新接回统一 HTTP 入口。

## 为什么保留 WebView 代理

`PixivLoginViewModel` 和 `BgmTurnstile` 仍真实消费 `AntiSniWebProxy`。该代理还依赖 `AntiSniDns`、`AntiSniSocket`、TLS 分片策略及分片工具；不能因为原生 HTTP 已使用 ECH 就把整套 sni 文件删除，更不能将 WebView 改为直连。

本次不修改上述两个消费者、代理及剩余 sni 文件，也不修改 `NetworkConfig` 的 `customResolve`、hosts、分片域名等字段。common expect 与各平台 actual 的参数继续保留，以维持跨平台接口兼容。保留代理不代表它已被验证具备 ECH；本次不宣称修复 WebView 的连接或安全性。

父任务已有的独立包名改动 `com.anglesgirl.bangumi.ech` 原样保留；不调整埋点、签名、更新逻辑或其他业务登录/通知功能。不触碰 XML 资源。已有生成的 baseline/startup profile 中可能仍含历史类名，本次不手工重写这些生成文件，它们不算源码消费者。
