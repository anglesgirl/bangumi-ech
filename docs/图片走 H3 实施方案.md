# 让图片走 H3（ECH + QUIC）实施方案

> 目的：把「浏览器飞快、App 很慢」的**协议差**补上。已实测：浏览器与 App 连的是**同一个 CF 端点**
> （你 zone 的 `172.64.229.6`），Pixiv 真实 IP（`210.140.139.x`）**完全不支持 QUIC**，
> 所以浏览器那次 H3 只能落在 CF。差的只是 **H3(QUIC) vs TCP+TLS1.3**。

## 一、边界（只做这一件事）

| 流量 | 传输 | 理由 |
|---|---|---|
| **图片 GET**（受保护图片域） | **H3 + ECH（ech-doh-h3-sdk）** | 匿名静态请求，不需 Cookie/登录态；占页面请求数最多，收益最大 |
| API / WebView / 登录 | **保持 OkHttp + Conscrypt（不动）** | 有认证、Cookie、拦截器、重定向语义，不该动 |

**回落必须是"ECH→ECH"**：H3 失败时回落到现有 Conscrypt+ECH 链路，**绝不回落明文 SNI**（fail-closed 不变）。
另加构建期/设置项开关，出问题一键切回纯 TCP 路径。

## 二、SDK 侧（复用 `/root/ech-doh-h3-sdk`）

1. **三个必修补丁确认在位**（技能 `quic-h3-quiche-pitfalls`）：随机 DCID、流控参数、ALPN 传裸名 `h3`。
2. **DoH 端点不能用 1.1.1.1**（国内已封）：`EngineConfig.dohServer` 指现有自有网关，
   `dohBootstrapIp` 用网关自带 IP（与 App 现有 bootstrap 一致）。
3. **ECH 配置来源要与 App 对齐**：SDK 默认查"目标域名自己的 HTTPS 记录"，
   而 P站系那份是**手写静态值、过期即失效** → 需要 SDK 支持**外部注入 ECH 配置**
   （或让它按现有策略去查 `cloudflare-ech.com` 的活值，再跨 zone 用于目标域名）。
   ← **这是 SDK 侧唯一必须新增的能力**，其余它都已具备。
4. 构建（CI 里做）：`cargo ndk` 出 `arm64-v8a`（+ `armeabi-v7a`）`.so`；
   按技能铁律：`-o` 指到 `jniLibs` 本身、vendor 后删多余 `libquiche*.so`、`llvm-nm -D` 验 JNI 符号。

## 三、App 侧落点

| 位置 | 改动 |
|---|---|
| `shared/core-native`（androidMain） | 放 SDK 的 Kotlin 绑定（UniFFI）与 `.so`；包一层 `EchH3Client`（单例、懒启动、可关闭） |
| Coil 图片加载 | 注册**自定义 Fetcher**：命中「受保护图片域」→ 交 SDK 取字节；其余走原路径 |
| 判定条件 | `BgmEchPolicy.isProtected(host)` 且属于图片域白名单（`pximg.net` / 图源域）才算 |
| 缓存 | 响应仍交给 Coil 的磁盘缓存（语义不变）；与现有 WebView 拦截缓存互不干扰 |
| 回退 | SDK 失败/超时 → 立即走现有 OkHttp+Conscrypt（同样带 ECH），不暴露 SNI |

## 四、验证

**CI**：编 `.so` → 验符号 → 断言 APK 内 `lib*.so` 存在且 ABI 正确 → 记录体积增量。
**真机**：同一张图，分别测 H3 与 TCP 两条路的耗时（App 内打点）；
用 SDK 自带诊断（`sent/recv/peer_err/stat`）确认 H3 真的建连成功、不是回落。

## 五、里程碑（一次一事）

- **M1**：只接管**一个**图源域（建议 `i.pximg.net`）→ 真机对比耗时 → 达标再往下。
- **M2**：扩展到全部受保护图片域。
- **M3**：评估是否给 API 也上 H3 —— **默认不做**（认证/重定向复杂度不值当）。

## 六、风险

- 新增 native 层：`.so` 体积 + 若干 MB；JNI 崩溃面（用开关 + 回落兜住）。
- 运营商对 UDP/443 限速或丢包时，H3 收益会缩水 → 由回落开关保证不至于更差。
- 与现有 ECH 策略**只能有一套真相**：SDK 与 `BgmEchDoh` 必须共用「活源 = cloudflare-ech.com」这条规则，
  否则又会出现"两边配置不一致"的老问题。
